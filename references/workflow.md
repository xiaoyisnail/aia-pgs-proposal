# iPGS+ 危疾险与储蓄险动态产品确定性流程

本文件是 `SKILL.md` 的页面状态与字段对照表。实现以真实页面状态为准：
每次操作后必须回读字段、路由或下一页面标志，不能仅以 click 没有抛错作为成功。

## 0. 环境与前置

新机器先按 `references/onboarding.md` 运行单一平台 bootstrap。只有输出
`ONBOARDING_OK` 才进入页面流程；不要把内部 npm 子步骤交给小白用户。

禁止连接或控制使用者已经打开的 Chrome；只运行本 Skill 的脚本，让
`launchPersistentContext` 创建独立自动化实例。

后续运行前：

1. 香港 VPN 已连接。
2. `npm run params:check -- params.json` 输出 `PARAMS_OK`；该命令不启动 Chrome。
3. `npm run setup:check` 列出的本地环境项全部通过并输出 `SETUP_OK`。
4. `npm run login` 可复用已有 Agency 会话。遇到 `MANUAL_LOGIN_REQUIRED` 时，
   提醒使用者在独立 Chrome 手动登录，脚本等到 Agency 首页才继续。
   Chrome 会恢复独立 profile 的上次会话，并优先访问受保护的 Agency 首页，避免
   不必要地触发新的登录挑战；若服务端会话有效，无需重新扫码。
5. 需要主动清除独立 Chrome 的 AIA 会话时才运行 `npm run generate:fresh -- params.json`。
   正常未登录由 `generate` 提示人工登录；iPGS+ 入口异常不等于登录失败。

`setup:check` 检查 Node、Chrome、Playwright 和 profile 隔离。出现
`SETUP_NOT_READY` 时，逐项完成每个 `❌` 下的处理指引。

### Agency 与 iPGS+ 入口排查

- 如果登录已成功，先保留原自动化进程和独立 Chrome；不跑 `login:fresh` 或重开。
  Agency 的登录端点可能在现有会话仍可访问首页时重新发起验证。不要把 iPGS+ 入口
  异常或电子服务页 HTTP 500 当作会话失效。
- 「電子服務」里的 `iPGS+` 是原生链接，可能在新标签页跳转。一次实测中鼠标按下
  命中链接、松开落到旁边的元素，Playwright 的点击返回但没有导航请求。对精确链接
  按 Enter，保留站点自身的跳转流程；不要抓 `href` 后拼接、强制打开或记录 SSO URL。
  必须检测同一 context 中新出现或发生导航的标签页，旧 iPGS+ 标签不算成功；等待
  `/transfer/` 完成和加载罩消失才开始填表。
- 若电子服务页出现「發生意外錯誤，請重試。」，脚本只在同一窗口刷新一次。曾实测
  文档 HTTP 200、电子服务后台请求 HTTP 500，页面没有入口。在 `IPGS_MANUAL_ENTRY`
  时，请使用者于原窗口检查提示或手动点一次 iPGS+，不要启动第二个进程；脚本会检测
  跳转并继续。默认等待最多 5 分钟，单份出单需保留现场时可从一开始加 `--keep-window`。
  该选项取消人工登录和 iPGS+ 入口的等待倒计时，并在失败后保留窗口，不会暂停表单
  其它步骤的超时。
- 排查只记录必要的状态码、域名和无敏感参数的路由，不输出 Cookie、OTP、JWT、
  客户字段或完整 SSO 链路。人工点入口后已验证可以继续到 PDF；Enter 修复已用本地
  Chrome 复现验证。友邦后台 500 时不宣称线上入口已通过全自动复测。
- 报告耗时时，单列人工扫码、入口接续等待及实际出单耗时；不要把等待人工回到电脑
  的时间当作浏览器填表速度。

## 1. 受保人资料（Step 1）

| 字段 | 操作 | 选择器 / 值 |
|------|------|-------------|
| 出生日期 | Playwright `fill` 后按 `Tab`，等待年龄回填 | 首个 DOB 输入框；`input[name="insuredAge"]` |
| 性别 | 点击对应 label，并验证 radio checked | 女=0 / 男=1 |
| 吸煙 | 危疾险按参数选择；储蓄险固定为非吸煙 | `insuredSmokeCode` |
| 職業 | 默认標準 | — |
| 居住地 | 按 label 找 MUI select，再选精确 option | `中華人民共和國` / `香港` / `澳門` |
| 声明与警告 | 只处理当前顶层可见弹窗 | `接受`、`確定` |
| 未出生投保提示 | 已出生受保人选择「否」，包括已出生的 0 岁儿童 | 只操作该弹窗内的「否」 |

成功门：`insuredAge` 等于参数年龄，声明已接受，并出现产品分类页。

## 2. 选择产品（Step 2）

- 危疾险点击 `危疾保障`；储蓄险点击 `儲蓄保險`。
- 按 `productName` 或可选 `productCode` 筛选产品卡，只有唯一结果才点击「選擇」。
- 名称/代码找不到时返回当前分类候选；匹配多个版本时返回 `PRODUCT_AMBIGUOUS`。
- 使用者不确定名称时运行 `npm run products:list -- params.json`；当前清单和验证
  状态见 `references/products.md`。
- 等待产品确认弹窗或 `/basicInfo/` 路由；若有确认弹窗，点精确的 `確定`。
- 等待服务端 loading cycle 结束，确认基本计划字段已经挂载。

成功门：路由含 `/basicInfo/`，并存在 `ownerSameWithInsured` 与
`premiumPaymentPeriod`。

## 3. 基本计划配置（Step 3）

### 3.1 通用持有人资料

| 项 | 字段 / 值 |
|----|-----------|
| 保单持有人 | `ownerSameWithInsured`: 同一人=1，不同人=0 |
| 持有人性别 | 不同人时填写 `sex`: 女=0，男=1 |
| 持有人 DOB/年龄 | 不同人时 fill DOB + Tab，并验证 `input[name="age"]` |
| 持有人居住地 | 不同人时按 label 选择 `payorRegion` |

受保人未满 18 岁时，无论输入如何都按不同人处理。每个 radio 点击后回读
`checked`。

### 3.2 危疾险

| 项 | 字段 / 值 |
|----|-----------|
| 繳付年期 | `premiumPaymentPeriod={premiumTerm}` |
| 額外保費 | 有 `paymentPatternOption` 时：是=1，否=0 |
| 繳費模式 | `paymentFrequency=1`（年繳） |
| 危疾保額部分 | `ciAdvancement=1`（100%） |
| 保额 | `input[name="sumAssured"]` |

`paymentPatternOption` 或 `ciAdvancement` 不存在时视为该产品不适用。使用者要求
额外保费=true 但控件不存在时返回 `PRODUCT_OPTION_UNAVAILABLE`；false 可以安全
跳过。保额 fill + Tab 后去掉逗号回读验证。OYS2 和 EOYS 已完整生成验证。

### 3.3 储蓄险

| 项 | 字段 / 值 |
|----|-----------|
| 货币 | MUI `貨幣` 下拉或固定 `currencyCode` |
| 保费缴付年期 | `premiumPaymentPeriod={premiumTerm}` |
| 缴费模式 | 多年缴=`paymentFrequency=1`；一次缴=`0` |
| 打开预算弹窗 | 点击可见且 enabled 的 `預算每年保費` |
| 预算每年保费 | `input[name="budgetPremium"]={annualPremium}` |
| 计算 | 点击弹窗中精确文本 `計算` |
| 系统计算的基本金额 | 等待弹窗关闭，回读 `input[name="sumAssured"]` |

货币和缴费年期必须是所选产品实际提供的值；选择年期后等待新
`paymentFrequency` 挂载并回读，不能接受重渲染前的旧状态。“预算每年保费”是
目标值，不是基本金额。禁止把 `annualPremium` 直接写入
`sumAssured`。实测目标 50,000 美元经系统计算得到基本金额 512,296，最终 PDF
年缴保费为 50,000.09 美元；这是产品计算的金额舍入，不应篡改基本金额强行抵消。

「預算每年保費」应使用 Playwright 的真实 click。页面几何顶层命中检查会在部分
渲染状态下错误地认为按钮被遮挡，不能据此跳过这个必要步骤。

GF 和 GP3 已完整生成验证。其他同类产品在共同字段不成立时必须报错停止。两类
产品都只有在「下一步」真实 enabled 时点击。

成功门：路由由 `/basicInfo/` 变为 `/rider/`。

## 4. 附加契约（Step 4）

默认全部不勾选，直接 `下一步`。

成功门：路由由 `/rider/` 变为 `/abstract/`。

## 5. 概要（Step 5）

展示計劃概覽表格（基本計劃 / 升級保障 / 附加契约 / 首年保費總額），核对后
处理储蓄险提领，再点 `下一步`。

### 5.1 不提领

`withdrawalPlan.enabled=false` 时不打开保单选项，沿用原流程。

### 5.2 同额提领

批量连续生成时，“保单选项”偶尔会在点击后超过 45 秒仍未挂载。先记录当前页面
状态，只按仍然可见的“保单选项”标签重试一次并等待 60 秒；仍未就绪则返回
`WITHDRAWAL_OPTIONS_LOAD_TIMEOUT`。大单批处理会等待会话释放并用新的独立
Chrome 重试该档，单档总尝试不超过 3 次。

- 进入“保单选项”后可能弹出保险业监管局保费征费提示；先确认顶层“确定”，再
  等待“以相同提取金额提取”，否则标签虽已点击但正文永远不会挂载。
- 计算后若完整 `withDraw-*` 结果表已经出现但仍停留 `/abstract/po`，只能在结果
  行数完整时重试“计算”一次；必须最终出现结果路由或“完成”按钮。
- 基本计划字段均已回读但“下一步”暂时 disabled，或概要提交后路由未变化时，
  先等待状态周期并在原页重试一次；禁止重新填值或连续点击。

仅支持 `以相同提取金額提取`、0% 增长率和 `減少基本金額`：

1. 等概要内容延迟挂载，点击精确文本 `保單選項`。
2. 视觉单选实际是无名隐藏 checkbox；按精确卡片文字定位最近的唯一 checkable，
   点击后验证 `checked`，再点 `開始設定`。
3. 等路由 `/abstract/po` 和提取金额字段挂载，切换到 `保單年度`。默认可能为
   “年龄”，不能直接按输入框顺序填写。
4. 从页面辅助文字读取 `最早第 N 年` 和 `最多第 N 年`。`endPolicyYear="last"`
   映射到实时最大年度；3 岁 GF 实测为 3–97 年。
5. 按 label 填起始年度、终止年度、目标每年金额。0% 字段需逐键输入 `0`；
   失焦后 DOM 可能显示空白，以后续储存/计算和结果表为准。
6. 选择 `減少基本金額`，确认第一次“部分退保”信息弹窗；点 `儲存`，等待
   `計算` enabled 后点击。
7. 确认第二次部分退保提示。路由进入 `/abstract/po-result` 后读取
   `input[name^="withDraw-"]`；年度数必须等于
   `endPolicyYear-startPolicyYear+1`，首末年度实际金额必须大于 0。
   中间年度金额以系统计算值为准，不要求强行等于目标金额。
8. 核对逐年结果后点 `完成` 返回概要。

GF 3 岁、5 年缴、预算年保费 50,000 美元、保单第 6–97 年每年提取 5,000 美元
已完整生成验证；PDF 为 33 页，现金提取表覆盖第 6–97 保单年度。

成功门：路由由 `/abstract/` 变为 `/setting/`。

## 6. 建议书选项（Step 6）

按稳定字段名填写，不按可见输入框顺序猜测：

| 字段 | 参数 |
|------|------|
| `lastName` | `insuredSurname` |
| `firstName` | `insuredGivenName` |
| `payorName`（不同持有人） | `payorSurname` |
| `payorFirst`（不同持有人） | `payorGivenName` |

其中 `payorName` / `payorFirst` 是 `type="search"`。全部 fill 后逐项回读，再点
「下一步」。服务端计算可能持续数十秒；等待真正出现的确认 dialog，点精确
`確認`，不要重复提交。提领页返回后 `/setting/` 可能先改变路由、后挂载表单；
最多等待 45 秒，确认当前持有人设置所需的姓名字段存在后再填写。同一人时仅等待
受保人的两个字段。

成功门：离开 `/setting/`，完成页出现「檢視詳盡建議書」。

## 7. 成功页（Step 7）

点 `檢視詳盡建議書`。

## 8. PDF 预览与保存

1. 跨当前页和新标签页等待 PDF.js：`PDFViewerApplication.pdfDocument.numPages > 0`。
2. 优先调用 `pdfDocument.getData()` 获取原始字节并写入目标文件。
3. 如果站点改为直接 PDF response 或 base64 JSON，使用网络响应作为后备。
4. 最后才尝试 viewer 的 `#download` 并监听 Playwright download。
5. 保存后必须验证文件至少 10 KB 且以 `%PDF-` 开头；失败时删除无效文件并报错。

## 9. 产品目录、简体文件名与储蓄险 IRR

- 默认根目录是 Skill 根目录下的 `计划书/`。
- 每份 PDF 保存到 `计划书/{简体产品名}/`；产品目录名和 PDF 文件名统一由香港
  繁体转换成简体。`outputDir` 若被覆盖，仍视为根目录并继续追加产品子目录。
- 危疾险出单默认只保存 PDF。若用户另要退保 IRR，见
  [香港重疾险退保 IRR](photo-comparison.md#香港重疾险退保-irr)。储蓄险 PDF 验证通过后，立即生成同目录
  `{PDF 文件名（不含.pdf）}_IRR表.xlsx`。
- 单份储蓄险再生成 `{PDF 文件名（不含.pdf）}_IRR说明图.png`；不提领与提领
  计划使用不同的数据模型和配色。

储蓄险 IRR 严格解析：

1. 从 PDF 首页按“年缴保费”和“保费供款年期”列坐标读取实际金额与年期，不使用
   文件名里的预算金额。
2. 只读取标题同时包含“详细说明”和“退保发还金额”的页面。
3. 每个数据行必须有 12 个数字列；取保单年度、年末年龄、缴付保费总额及
   `(A)+(B)+(C)` 的退保发还金额总额。
4. 保单年度必须从 1 连续到最后年度；缺页、重复或断号立即返回 `IRR_*`。
5. 第 N 年现金流为：`t=0..min(N,缴费年期)-1` 每年期初支付实际年缴保费，
   `t=N` 收取该年退保发还金额总额；计算年化 IRR。
6. Excel 主表同时保留脚本结果与 Excel `IRR` 公式核验，现金流放在独立核验表。
7. 带提领 PDF 仍按“详细说明”基础计划口径计算，不读取“现金提取后”页，也不把
   提取金额计入 IRR；必须在工作簿中显著披露。

储蓄险说明图规则：

1. 用正式版 Chrome 的独立无痕后台进程渲染 HTML/CSS 为 PNG，不连接日常 profile。
2. 不显示具体产品名；统一标题为“香港友邦储蓄保险计划”，副标题必须含投保年龄、
   供款年期和总保费。
3. 不提领表格选取静态回本年度、其后的整十保单年度及最后保单年度，展示年末年龄、
   退保发还金额和相对总保费倍数。
4. 不提领 IRR 里程碑取显示值首次达到约 3%、4%、5%、6%、6.5% 的保单年度。
5. 提领版只读取不含“悲观情景”的“现金提取后之退保发还金额”页面；每行必须有
   9 个数字列且保单年度连续。
6. 提领版从第一个整十保单年度到最后年度展示提取后退保金额、累计提取、两者
   合计和相对总保费倍数；综合 IRR 现金流包含期初保费、逐年期末提取和最终退保。
7. 不提领使用青绿色，提领使用紫色；保持同一字体、网格、卡片和信息层级。

美元大单储蓄规则：

1. `productType=savings`、货币为美元且预算年缴保费不低于 50,000 时，
   `scripts/generate.mjs` 自动分流到六方案批处理。
2. 先生成不提领 PDF，并以首页实际年缴保费乘实际缴费年期作为比例基数。
3. 五档每年提领金额为实际总保费的 `6.4%、8.8%、11.6%、16.2%、22%`，
   四舍五入到整美元；对应从第 `6、11、15、20、25` 保单年度开始，终止年度固定
   使用页面最大值。
4. 每一档都必须完成 PDF 和 IRR 表，不单独生成提领说明图。分析书读取非悲观主情景逐年提领
   表，校验实际开始年度、同额提领、实际保费/年期/投保年龄一致，再汇总累计提领、
   最后年度退保价值及合计金额。
5. 不提领详细说明的 12 列数据还要读取最后一列人寿保障总额；分析书展示第 30
   保单年度及可用的 70/80/90/100 岁人寿保障、退保价值和总保费倍数。
6. 只有 6 份真实计划书全部通过后才写入
   `{不提领计划书文件名}_大单储蓄分析书.pdf`；任何 `SAVINGS_ANALYSIS_*` 错误都
   禁止用估算值或参考样例数字补齐。
7. 参考图的产品特点面板只用于环宇盈活；其他产品保留数值版式与配色，但必须换成
   中性条款提示，不能把环宇盈活的专属产品特点套用到其他产品。
8. GF 真实六方案回归中，成功子流程合计约 14–15 分钟；3 次瞬态自动重试后整批
   约 21 分 42 秒完成。使用者侧应预留 15–25 分钟。

- 危疾险：`{产品}_{性别}{年龄}岁_{地区}_USD{保额}_{年期}年缴.pdf`
- 储蓄险不提领：基本名称后附 `_不提取.pdf`
- 储蓄险同额提领：基本名称后附
  `_第{起始}至{终止/最后}年每年提取{货币代码}{金额}_减少基本金额.pdf`

- GP3 例：`盈御3_男3岁_大陆_USD50000每年_5年缴_不提取.pdf`
- 大单分析书例：
  `环宇盈活_男3岁_大陆_USD50000每年_5年缴_不提取_大单储蓄分析书.pdf`

## 10. 已有 PDF 处理

用户直接提供储蓄险计划书 PDF 时，不执行 Agency/Outlook/HK 网络流程：

1. 首次运行平台 bootstrap 并传 `--pdf-only`；只有 `PDF_TOOLS_OK` 才继续。
2. 单份 PDF 默认生成 IRR Excel 和说明图；`--irr` 或 `--summary` 可只生成指定
   结果。
3. 分析书接受 2–6 份：恰好 1 份不提领和 1–5 份每年同额提领；全部使用同一
   严格解析器读取实际数据，不能依赖文件名。
4. 自动识别不提领基准，并按提领实际起始年度和提领额比例排序；输入顺序不限。
5. 产品、货币、投保年龄、实际年缴保费和缴费年期必须一致，当前分析模板只接受
   美元计划；任一不一致返回 `SAVINGS_ANALYSIS_*`。
6. 输出默认放在源 PDF 同目录；`--output-dir` 可集中输出。源 PDF 只读，不移动、
   改名或覆盖。
7. 2–5 份输入生成对应数量的真实方案行；基准加 5 档提领最完整地对应参考版式。

统一入口为 `npm run from-pdf -- [选项] "<PDF>" [...]`。只有看到
`EXISTING_PDF_OUTPUT_OK` 且计数与用户要求一致，才报告完成。

## 11. 排错速查

- `BROWSER_PROFILE_IN_USE` → 只关闭本 Skill 创建的自动化 Chrome 后重试；禁止
  `pkill`、`killall`、`taskkill` 或关闭使用者日常 Chrome。
- `DEFAULT_CHROME_PROFILE_FORBIDDEN` → `AIA_PGS_PROFILE_DIR` 与日常 Chrome
  用户目录重叠；改回独立目录，不能绕过。
- `MANUAL_LOGIN_REQUIRED` → 提醒使用者登录独立 Chrome，并保持当前脚本运行。
- `SETUP_NOT_READY` → 按输出的全部 `❌` 和“处理”指引补齐本地环境。
- `PARAMS_*` / `PRODUCT_UNSUPPORTED` → 修正对应字段，再运行
  `npm run params:check -- params.json`；不要通过启动浏览器试错。
- `PRODUCT_CARD_NOT_FOUND` → 运行 `products:list` 并核对分类和产品名称。
- `PRODUCT_AMBIGUOUS` → 使用更完整名称、货币版本或候选中的代码。
- `PRODUCT_OPTION_UNAVAILABLE` → 使用者要求了该产品没有的可选项，不能绕过。
- `CURRENCY_NOT_AVAILABLE` / `PAYMENT_FREQUENCY_UNAVAILABLE` → 修正为页面提供的组合。
- `MANUAL_LOGIN_TIMEOUT` → 重新运行并在独立 Chrome 完成手动登录。
- `STEP3_NEXT_NOT_CLICKED` → 回查各 radio 的 checked 和保额实际值，不要 force click。
- `ANNUAL_PREMIUM_BUTTON_NOT_FOUND` → 该产品可能不属于共同储蓄险字段模型；停止适配。
- `ANNUAL_PREMIUM_NOT_SET` → 回查 `budgetPremium` 格式化后的数字。
- `ANNUAL_PREMIUM_CALCULATE_NOT_FOUND` → 保留弹窗状态，检查“计算”按钮是否改版。
- `ANNUAL_PREMIUM_CALCULATION_TIMEOUT` → 等待 iPGS+ 服务恢复后重跑；不要改为直接
  填写 `sumAssured`。
- `WITHDRAWAL_YEAR_OUT_OF_RANGE` → 按页面实时最早/最多年度修正起止年度。
- `WITHDRAWAL_*` → 保留当前页面检查卡片挂载、两次提示确认、结果首末年度和行数；
  不能直接跳到概要下一步。
- `STEP6_CONFIRM_TIMEOUT` → 不要连续点击下一步；保留页面与错误输出检查服务端响应。
- `PDF_INVALID` → 文件不是完整 PDF，不得交付；重新生成并检查 quotation/PDF response。
- `IRR_PREMIUM_*` → 首页实际年缴保费或缴费年期无法确定；不得用文件名预算替代。
- `IRR_DETAIL_TABLE_*` → “详细说明”逐年表缺失或保单年度不连续；保留 PDF 并
  停止生成 IRR。
- `IRR_REPORT_FAILED` → PDF 已保存但 IRR 表未完成；不能把整次任务报告为完全成功。
- `IRR_WITHDRAWAL_*` → 提领主情景 9 列逐年表缺失或断号；禁止使用基础计划图替代。
- `IRR_IMAGE_*` → IRR Excel 已保存但 PNG 未完成；检查正式版 Chrome 后重跑。
- `EXISTING_PDF_*` → PDF 无效、重复、数量或选项不合法；按错误修正输入列表。
- `SAVINGS_ANALYSIS_*` → 多方案缺件、基础字段不一致、提领并非同额或分析书
  渲染失败；保留已完成文件，修复后整批重跑，不能交付不完整分析书。
- 遇验证码 / Cloudflare → 立即暂停转人工。
